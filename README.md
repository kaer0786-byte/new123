# AI 开发团队 · 使用指南

一套在 Claude Code 中运行的「产品经理 → UI/UX 设计师 → 前端工程师」三角色协作工作流,把一个想法一步步变成可运行的前端项目。

## 工作流程

```
你的想法 ──/pm──► docs/PRD.md ──/design──► docs/DESIGN_SPEC.md ──/dev──► 完整前端项目
```

## 快速开始

在 Claude Code 中打开本仓库,按顺序执行三个命令:

### 第 1 步:需求分析
```
/pm 我想做一个个人记账网页应用
```
产品经理会先追问关键问题,然后输出 `docs/PRD.md`(功能清单、优先级、页面结构、核心流程)。看完不满意直接说,改到满意为止。

### 第 2 步:设计方案
```
/design
```
设计师读取 PRD,与你确认风格方向后输出 `docs/DESIGN_SPEC.md`(色彩/字体/间距规范、组件规范、页面原型、交互规范)。

可以带补充要求,例如:`/design 我想要深色科技风,移动端优先`

### 第 3 步:开发实现
```
/dev
```
前端工程师读取 PRD 和设计规范,确认技术选型后写代码,交付可运行的项目并附运行说明和完成情况清单。

## 使用技巧

- **每步都可以对话迭代**:命令只是切换角色,切换后可以继续多轮对话打磨产物,满意再进入下一步。
- **可以跳步**:没有 PRD 直接 `/design` 时会提醒你;坚持跳过也可以,Agent 会注明假设。
- **改需求要回上游**:需求变了先 `/pm` 更新 PRD,再 `/design` 同步设计,最后 `/dev` 改代码,避免文档和代码脱节。
- **自然语言也行**:不用命令,直接说「切换到产品经理模式,分析我的需求」效果相同。

## 目录结构

```
.claude/commands/   # 斜杠命令:/pm /design /dev
prompts/            # 各角色提示词(协调者/产品经理/设计师/前端工程师)
docs/               # 阶段产物:PRD.md、DESIGN_SPEC.md
src/                # 开发阶段生成的项目代码(默认位置)
```

## 自定义

想调整某个角色的行为,直接编辑 `prompts/` 下对应的提示词文件即可,命令会自动引用最新内容。
